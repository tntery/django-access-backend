# Verigate Smart Access Control
## Portal user guide

This guide explains how authorised Belgravia Sports Club portal users can sign in, find a user record, and understand the access information shown in the portal.

> The portal is an administrative information and access-management tool. It is not a self-service membership registration page or a button for opening a door. Your available actions depend on the role assigned to your portal account.

## 1. Sign in

1. Open the portal using the web address supplied by Belgravia Sports Club.
2. Select **Login** if you are not already on the sign-in page.
3. Enter the username and password supplied by your portal administrator, then select **Login**.
4. Check the username and role shown in the top navigation. Select **Logout** when you have finished, especially on a shared device.

Portal accounts are created by an administrator; there is no self-registration link. If you cannot sign in, your account is inactive, or you have forgotten your password, contact your portal administrator or use the support contacts at the end of this guide. Do not send your password to anyone.

## 2. Understand your role

- **Viewer** — can view user connections, account details, linked access IDs, access decisions, and recorded access events.
- **Staff** — has Viewer access and can manage mappings, linked access IDs, and a user's access decision.
- **Admin** — has Staff access and can also manage portal users, application settings, and user synchronisation.

The role shown beside your username indicates your portal permissions. Portal roles are separate from physical membership and do not themselves guarantee that a credential will open a door.

## 3. Find a user

After signing in, the **User Connections** page shows the user list and summary counts.

1. Open **Quick actions** to see the search and filter controls.
2. Search by a name, accounting user ID, narration/display name, or access ID. You can also filter by **Connected / Not Connected** status and **Staff / Member** classification.
3. Select **Filter** to apply your choices, or **Clear** to remove them.
4. If results span more than one page, use the page links below the list.
5. Select **View** beside a record to open its details.

The list can show the user's name, classification, balances, whether an access ID is linked, and the current access-decision type. Information such as balances is account information; it is not a real-time device status.

## 4. Read a user's details

The details page may include:

- **Account details** — the accounting user ID, name, classification, and available account information.
- **Mapping access decision** — whether the record uses **Auto**, a manual **Grant**, or a manual **Reject**.
- **Linked access IDs** — credential identifier, authentication type (for example, card, biometric, or PIN), assigned device/location, configured device status, and last successful sync if recorded.
- **Access summary and events/logs** — recorded grant/reject decisions and event details, including time and device where known.

Use **Back to User Connections** to return to the list. Events are records of attempts attributed to that user; an event list may not include unattributed attempts.

### What the status labels mean

- **Connected** means an access ID is linked to the user. It does not mean access is currently granted.
- **Not Connected** means the portal has no enabled linked access ID for that user.
- **Active / Inactive** is the device's configured status, not a live connectivity test.
- **Last successful sync** shows the last successful device sync recorded by the portal. It may not reflect the device's current state.
- **Grant / Reject** is the recorded access decision. If no events are shown, the portal has no recorded event attributed to that mapping.

### Automatic and manual decisions

- **Auto** uses the club's configured authorisation rules. In Auto, Staff are granted access; Members are evaluated using those rules.
- A manual **Grant** or **Reject** overrides the automatic decision for every access ID linked to that mapping.
- A disconnected ID or inactive device still rejects access. A device that is offline receives changes at its next successful sync, so updates may not take effect immediately.

If you believe a decision or user record is wrong, contact the club or portal administrator. Do not attempt to correct a record unless your role and club procedures authorise you to do so.

## 5. Staff and Admin actions

Only users with the appropriate role see management controls.

- **Staff** can create or edit mappings, connect or update access IDs, disconnect linked IDs, and save a manual access decision. Review the selected user, credential, device, and decision before saving. A disconnected ID is protected from automatic reconnection; reconnect it through **Connect access ID** if authorised.
- **Admin** can also use **Portal users** to create or edit portal accounts and roles, use **Settings** to manage authorisation configuration, and synchronise user data from the accounting system.
- When an administrator synchronises users, the list may be updated and users deleted from the external accounting system may be removed. Use this action only when authorised and when the club's procedures call for it.
- Some changes are applied to a device only when that device next synchronises. Do not promise an immediate access change based only on a successful save in the portal.

If a management control is missing, your role may not permit that action. Contact an administrator rather than sharing login details or using another person's account.

## 6. Get help

When reporting a problem, include the user's name or accounting user ID, the approximate time of the attempt, the location/device if known, and the decision displayed by the portal. Share credential identifiers or personal information only through a private, approved channel. Never include your portal password.
